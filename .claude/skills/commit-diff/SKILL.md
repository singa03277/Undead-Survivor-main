커밋을 이전 상태와 비교해서 변경점을 정리해 줘. 파일은 수정하지 말고 결과만 보여 줘.

비교 대상: $ARGUMENTS

## 비교 대상 정하기

- 비어 있으면 `HEAD`를 첫 번째 부모(`HEAD^1`)와 비교한다.
- 커밋 하나가 주어지면 그 커밋을 첫 번째 부모와 비교한다.
- `A..B` 같은 범위가 주어지면 그 범위 전체를 비교한다.
- 부모가 없는 첫 커밋이면 커밋에 들어 있는 파일 전체를 새로 추가된 것으로 본다.
- 병합 커밋이면 병합 커밋임을 밝히고 첫 번째 부모와 비교한다.

## 확인 순서

1. `git diff --stat`으로 전체 규모와 파일 목록을 먼저 확인한다.
2. `Codes` 폴더의 `.cs` 파일은 실제 diff를 읽는다.
3. `Data` 폴더의 `.asset` 파일은 실제 diff를 읽고 바뀐 값을 찾는다.
4. 다음 파일은 diff 본문을 읽지 않고 개수와 경로만 파악한다.
   - `.meta` 파일
   - `.png` 등 이미지와 사운드 파일
   - `.unity`, `.prefab` 파일 (수치나 참조 변경을 확인해야 할 때만 필요한 부분을 읽는다)
   - `Library`, `Temp`, `Logs` 폴더의 파일

## 결과 형식

해당 내용이 없는 항목은 생략하고, 아래 순서로 정리한다.

- **요약:** 커밋 해시와 메시지, 변경 규모, 핵심 변화를 한두 문장으로 쓴다.
- **코드 변경:** 파일별로 이전과 지금의 동작 차이를 `파일경로:줄번호`와 함께 쓴다.
- **데이터 변경:** 무기와 아이템 수치는 `이전 값 → 지금 값` 형태의 표로 쓴다.
- **추가·삭제·이동된 에셋:** 폴더 단위로 묶어서 쓴다.
- **확인이 필요한 부분:** 버그 위험이나 커밋 메시지와 다른 내용처럼 diff에서 실제로 확인한 것만 쓴다.

diff에서 확인되지 않는 내용은 추측해서 쓰지 않는다.
