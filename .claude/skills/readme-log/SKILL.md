커밋의 변경 내용을 정리해서 저장소 최상위의 `README.md`에 기록해 줘.

기록할 커밋: $ARGUMENTS

비어 있으면 `HEAD` 커밋 하나를 기록한다. 범위가 주어지면 범위 안의 커밋을 날짜별로 나눠서 기록한다.

## 내용 파악

커밋 메시지만 보지 말고 실제 변경 내용을 확인한다. 코드(`.cs`)와 데이터(`.asset`)는 diff를 읽고, `.meta`와 이미지 파일은 경로만 파악한다.

## 작성 형식

```markdown
## YYYY-MM-DD
### 소제목
- 바뀐 부분 정리
```

- 날짜는 작성한 날이 아니라 **커밋한 날짜**를 쓴다.
- 소제목은 변경의 주제를 짧게 쓴다. 커밋 메시지를 그대로 옮기지 않는다.
- 한 커밋에 주제가 여러 개면 소제목을 나눈다.
- 목록은 파일 이름 나열이 아니라 게임에서 무엇이 달라졌는지를 중심으로 한국어로 쓴다.

## 작성 위치

- 기존 "진행 상황" 목록 아래에 적고, 최신 날짜가 위로 오게 한다.
- 같은 날짜의 제목이 이미 있으면 새로 만들지 말고 그 아래에 추가한다.
- 같은 커밋의 내용이 이미 적혀 있으면 중복으로 적지 말고 알려 준다.

## 지켜야 할 것

- "완료된 항목"과 "진행 상황" 목록은 커밋 내용상 상태가 분명히 바뀐 경우에만 고치고, 고쳤다면 결과에 알린다.
- `README.md` 외의 파일은 수정하지 않는다.
- 사용자가 요청하기 전에는 커밋하지 않는다.
- 작성을 마치면 추가한 내용을 보여 준다.
